## 💡 Общая задумка
 Пользователь создаёт анкету, где указывает кем работает или учится, хобби и увлечения, а также музыкальные предпочтения и загружает свою фотографию к себе в профиль. После регистрации и заполнения анкеты пользователь попадает в чат, где ему показываются различные анкеты других пользователей. Пользователь может поставить лайк другому пользователю и при взаимном лайке от другого пользователя происходит переход в личную переписку, где пользователи знакомятся и общаются. Нужна система модерации того, что происходит в приложении, как при регистрации и заполнении анкеты, так и в личной переписке. Необходимо придумать уникальную фишку моего приложения.

## 🚧 Возможные проблемы

- Могут возникнуть проблемы с модерацией. Это нужно предусмотреть. Нужно также учитывать какая будет регистрация и как будет проверять пользователей на клоны аккаунтов. - Также нужно предусмотреть модераторов, которые и будут контролировать чаты и регистрацию. С системой мэтчей проблем не должно возникнуть. Предусмотреть удобный пользовательский интерфейс. 
-  Модерация и регистрация планируется, но это сложно и нужно много людей. Пока это решается просто текстовым чатом без возможности отправлять изображения, голосовые сообщения и видео.
- Пока у меня нет уникальной фишки приложения и оно может просто никого не заинтересовать
- Также для удержания пользователя в ожидании ответа на его лайк можно добавить мини игры. Это можно сделать как отдельное окно с меню выбора игр.
- Добавлен чат с техподдержкой и если пользователю необходимо будет связаться с техподдержкой ему просто нужно лайкнуть этот профиль. Возможно пользователь не разберется как написать разработчикам, поэтому лучше сделать так, чтобы лайк у техподдержки стоял по умолчанию у всех, но возможно и текущая реализация не плоха.
- В данный момент не совсем понятно что не так с контекстным меню, при нажатии на функцию переслать возникает ошибка и программа аварийно завершается. Пока не знаю как решить эту проблему, но она связана с сигналом. 1 сигнал работает как нужно, а 2 не работает. Эти сигналы находятся на 4 окне и должны сработать на 5 окне, но это не работает.
- Необходимо полностью доделать апи и совместить его с клиентсой частью приложения. Сейчас возникают ошибки то в апи, то в клиентской части. Нужно в этом подробно разобраться.
- Проблемы с токеном, сервер отправляет его на клиент, но обратно не принимает и я пока не знаю как это можно исправить. Возможно у меня разный тип авторизации на клиенте и на сервере. Также вполне возможно что в токене нет необходимых данных или что-то еще.


## 💻 Стек технологий

- Языки и Фреймворки:
	- Клиент - C++ Qt. С++ - разработка desktop приложения. Для него будет использоваться framework QT, так как это наиболее популярный framework для построения графического интерфейса и со знанием QT можно легко найти работу.
	- Postgre SQL - для взаимодействия с бд. В бд будет хранится вся информация. Наиболее популярный диалект SQL, зная который также не сложно найти работу.

	- Qt Creator
	- Visual Studio
	- Visual Studio Code

## 🔌 API Endpoints

 Адрес сервера -> **`http://localhost:5002`**

 ### **1 Окно (Аутентификация) 🔐**
 - **`POST /api/auth/login`**

 Отправка учетных данных (логин/пароль) для аутентификации и создания сессии.
 - **`POST /api/auth/register`**

 Создание новой учетной записи пользователя.

 ---

 ### **2 Окно (Анкета пользователя) 📝**
 - **`GET /api/users/me`**
 - **`GET /api/users/{id}`**

 Получение данных текущего пользователя или пользователя по ID для заполнения формы.
 - **`PUT /api/users/me`**
 - **`PATCH /api/users/me`**

 Полное или частичное обновление данных профиля пользователя. PUT если заменяем всю анкету, PATCH если обновляем только измененные поля.
 - **`POST /api/users`** (если создает нового) или 
 - **`PUT /api/users/me`** (если обновляет существующего)

 Зависит от контекста. Если это окончательное сохранение новой анкеты после регистрации - POST. Если редактирование существующей - PUT.
 - **`GET /api/users/me`**

 Получение данных текущего пользователя.
 - **`GET /api/users/{login}/photo`**
 - **`GET /api/assets/photos/{filename}`**

 Получение файла фотографии пользователя.

---

### **3 Окно (Просмотр анкет) 👀**
 - **`GET /api/profiles`**

 Получение списка анкет для просмотра. Логин текущего пользователя может передаваться в заголовках для исключения его из результатов.
 - **`POST /api/reactions`**

 Создание новой реакции (лайк/дизлайк) на целевую анкету. Тело запроса: `{targetUserId: 123, type: "like"}`
 - **`GET /api/profiles?sort=criteria`**

 Сортировка обычно выполняется на сервере. Клиент просто добавляет параметры сортировки к запросу на получение анкет.

---

### **4 Окно (Уведомления) 🔔**
 - **`GET /api/notifications`**

 Получение списка уведомлений для текущего пользователя.
 - **`POST /api/reactions`**

 Аналогично saveReaction - создание реакции в ответ на уведомление.
 - **`GET /api/users/me`** (клиент должен хранить ID после логина)

 Получение ID текущего пользователя, но лучше чтобы клиент сохранял это после успешного логина.
 - **`GET /api/matches/check/{targetUserId}`**

 Проверка наличия взаимной симпатии с конкретным пользователем.
 - **`GET /api/users/{userId}`**

 Получение подробной информации о конкретном пользователе при клике на элемент списка.

---

### **5 Окно (Чат) 💬**
 - **`POST /api/messages`**

 Создание и отправка нового сообщения. Тело: `{receiverId: 123, content: "Текст сообщения"}`
 - **`GET /api/messages?userId={receiverId}`**

 Получение истории сообщений между текущим пользователем и выбранным собеседником.

 - **Удалить сообщение** - **`DELETE /api/messages/{id}`**
 - **Ответить на сообщение** - **`POST /api/messages`**
 - **Изменение сообщения** - **`PATCH /api/messages/{id}`**
 - **Копировать сообщение** - **`GET /api/messages/{id}`**

 - **Закрепить сообщение** - **`POST /api/chats/{chatId}/pinned-messages`**
 - **Пожаловаться на сообщение** - **`POST /api/reports`**

 Контекстное меню	

 Закрепить сообщение, Пожаловаться на сообщение - дополнительные  операции для контекстного меню, они еще не рализованы и они опциональные и планируются в будущем
